# مشاهدهٔ تکراری تطبیق مرکز و سیاست — گشت چندگامی

این آزمایش **صرفاً مشاهده‌ای است، نه الگوریتم آموزش سیاستِ نهایی**؛ به بخش پاداش‌دهی قدیمی وابسته نیست. هدف بررسی این است که اگر مرکز کلاس را به‌عنوان توزیع هدف بگیریم، در تمام وضعیت‌های گشت سیاستِ نزدیک‌کننده به آن را محاسبه کنیم و مرکز حاصل از گشت را اندازه بگیریم، چه تغییری در مراکز، جدایی و دقت طبقه‌بندی رخ می‌دهد.

## سازوکار دقیق

1. مرکز هدف اولیهٔ کلاس `c` برابر `(1-epsilon)*one_hot(c)+epsilon/K` است. **این مرکز واقعی داده نیست.**
2. در هر مبدأ آموزشی `o` با کلاس شناخته‌شدهٔ `c=y[o]`، برای **هر گرهٔ جاری** `j` (نه فقط مبدأ) ماتریس `Q[j,feature,label]` را از وزن‌های کرنل روی دادهٔ مرجع محاسبه می‌کنیم. نمونهٔ جاری و مبدأ اصلی از مقاصد انتقال حذف می‌شوند؛ ویژگی ناموجود/بدون مقصد حذف می‌شود.
3. روی سیمپلکس ویژگی‌های مجاز، `pi* = argmin_pi JSD(Q[j]^T pi, V_target[c])` را به روش Frank–Wolfe با جست‌وجوی خطی محدب **تقریبی** حل می‌کنیم؛ بیشینهٔ dual gap در نتایج ذخیره می‌شود. انتخاب از بین ویژگی‌ها تصادفی است، نه `argmax` قطعی.
4. گشت‌های چندگامی با توزیع طول هندسی `beta` (برش `max_steps`) اجرا می‌شوند. هر گشت بردار برچسب‌های دیده‌شده را با `lambda^(step-1)` وزن‌دهی و **درون همان گشت** نرمال می‌کند. بازنمایی هر نمونه، میانگین گشت‌هاست.
5. مراکز **واقعی** از میانگین بازنمایی نمونه‌های آموزش هر کلاس ساخته می‌شوند. مرکز هدف دور بعد: `(1-eta)*V_target + eta*V_realized`.
6. در هر دور، مراکز هدف، مراکز واقعی، جابه‌جایی، `T/TNL/BT/BTNL/I`، فاصلهٔ مراکز، فشردگی و معیارهای نمونه‌ها، احتمال شروع ویژگی‌ها و خطای حل عددی ثبت می‌شوند.

## ارزیابی و احتیاط مهم دربارهٔ برچسب‌ها

- سیاست گشت آموزشی از **برچسب واقعی مبدأ** برای تعیین مرکز هدف استفاده می‌کند؛ بنابراین `train_oracle_target` **دقت قابل استقرار نیست** و نباید با دقت یک طبقه‌بند معمولی هم‌ارز شمرده شود.
- در اعتبارسنجی، هیچ برچسبی برای ساخت سیاست وارد نمی‌شود. برای هر کلاس فرضی `c` یک گشت مستقل تحت مرکز هدف `V_target[c]` اجرا شده و فاصلهٔ بازنمایی حاصل با مرکز **واقعی آموزش** آن کلاس محاسبه می‌شود؛ برچسب فقط بعد از تمام پیش‌بینی‌ها برای گزارش دقت استفاده می‌شود. این قاعدهٔ «هر فرض کلاس یک گشت» ممکن است به تطبیق مصنوعیِ همهٔ فرض‌ها با مراکز خودشان منجر شود؛ بنابراین قدرت تفکیک آن باید جداگانه سنجیده شود.
- خطای تطبیق مرکز و کاهش آن **به معنی همگرایی ثابت‌شده یا بهبود تعمیم نیست**؛ حل عددی تقریبی، طول گشت برش‌خورده و مونت‌کارلو هستند.
- دادهٔ آزمون (`test.npz`) در این آزمایش **استفاده نشده** است. تنها `train` و `validation` لازم‌اند. برای بررسی همگرایی و کیفیت واقعی باید بذرها، مجموعه‌داده‌ها و تعداد گشت‌های دیگر را آزمایش کرد.
- پیاده‌سازی آزمایش از `walks.ReferenceGraph` و `metrics` اصلی پروژه استفاده می‌کند. برای سیاست‌های وابسته به مبدأ، شمارنده‌های برچسب `Q` با کسر وزن مقصد ممنوع از وزن‌های ذخیره‌شدهٔ همان گراف محاسبه می‌شوند.

## اجرای مجدد

از ریشهٔ مخزن:

```bash
python code/data_generator/generate.py --config code/data_generator/config.json --out generated_data
python code/experiments/center_matching_observation/observe.py \
  --train generated_data/train.npz \
  --validation generated_data/validation.npz \
  --policy code/policy_evaluator/policy_uniform.json \
  --rounds 6 --eta 0.5 --epsilon 0.08 \
  --walks 300 --optimizer-steps 65 --seed 20261104 \
  --out code/experiments/center_matching_observation/results/observational_6round_final.json
```

برای اجرای دورهای بیشتر از همان نقطه، مقدار `--rounds` را به تعداد کل دورهای موردنظر تغییر دهید و `--resume` را اضافه کنید؛ گزارش JSON و CSV در پایان **هر تکرار** به‌روزرسانی می‌شوند. با `python -m unittest discover -s code/experiments/center_matching_observation -p 'test_*.py' -v` تست‌ها را اجرا کنید. وابستگی اجرایی فقط NumPy است.
