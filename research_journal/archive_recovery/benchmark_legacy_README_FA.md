# شواهد منحصربه‌فرد تاریخی benchmark_v1 — مجموعهٔ گزیده

**وضعیت:** `HISTORICAL_CURATED_EVIDENCE`، بدون آموزش جدید و بدون ترفیع اعتبار علمی.

این پوشه خروجی‌های یکتای پژوهش قدیمی و تصمیم‌های مرحله‌ای R03 را از فضای اجرای فعال `benchmark_v1/` جدا می‌کند. جابه‌جایی‌ها از طریق **همان Git blob** انجام شده و بایت فایل‌ها تغییر نکرده‌اند. جدول کامل مسیر اصلی، مقصد و Git blob SHA در `MOVE_MANIFEST.json` ثبت شده است.

**منبع رسمی ۷۶ اجرا:** `code/experiments/standard_policy_comparison/results/` شامل چهار ZIP با checksum اصلی و جدول‌های `master_runs_76.csv`، `center_only_metrics.csv` و `coverage_manifest_76.json` است. این نسخه‌ها حفظ شده‌اند؛ جایگزین نتایج پذیرفته‌شده نمی‌شویم.

## سازمان‌دهی

- `results/`: خروجی‌های متمایز وارون‌سازی ۴ سیاست، بازارزیابی ۷ checkpoint، گزارش هشت checkpoint هدف جایگزین، خلاصه سیاست کلاس‌شرطی و مرجع هندسه بیزی.
- `r03_p1_provisional/`: گزارش‌ها و داده‌های **پیش‌نویس تاریخی** P1؛ نشان‌دهنده پذیرش مستقل همه معیارها نیست.
- `r03_p3_publication_gates/`: ماتریس تصمیم ۵۵×۴ و تحلیل امکان انتشار؛ وضعیت تاریخی خود را نگه می‌دارد.
- `r03_full_76_candidate/`: گزارش بازیابی، جدول CSV پوشش و budget اصلی که در بسته رسمی دقیقاً همتای بایتی ندارند.
- `MOVE_MANIFEST.json`: فهرست 20 فایل جابه‌جا‌شده، اندازه و Git blob اصلی.

**توجه علمی:** رأی `ACCEPT_QA76_CENTER_ONLY` تنها ۷۶ مرکز × ۱۱ معیار (=۸۳۶ مقدار) را شامل می‌شود؛ ۴۴ شناسه دیگر خودکار پذیرفته نشده‌اند. KL تاریخی clipped، KL دقیق support-aware نیست. داده‌های مرحله‌ای و P3 با رأی ممیزی نهایی اشتباه نشوند.

## چرا چند فایل از benchmark_v1 باقی مانده‌اند؟

`engine.py`، `policy_interface.py`، `snapshot_pipeline.py`، `report_snapshot.py`، کدهای بازسازی و تست‌های موتور هنوز توسط سایر آزمایش‌ها مصرف می‌شوند. حذف یا جابه‌جایی آن‌ها بدون اصلاح importها، تست و CI مجاز نیست. چهار ZIP اصلی در مسیر §۴.۱۲ هستند و اسکریپت‌های قدیمی باید همان‌ها را بخوانند.
