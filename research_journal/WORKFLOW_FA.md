## ۱. منشور Git و مأموریت
1. **تنها شاخه دائمی: `main`.** برای مأموریت دارای تغییر، ابتدا HEAD زنده `main`، Issues/PRهای مرتبط و پوشهٔ شواهد را بازیابی کن. فقط یک شاخه موقت از `main` بساز، مانند `research/<slug>-01`, `experiment/<slug>-01` یا `editorial/<slug>-01`. نام مأموریت در commit و PR باشد. اگر همان شاخه موجود است، شاخه جدید نساز.
2. هر مأموریت: شناسه، پرسش، مالک، فرض‌ها، محدودیت فایل/منبع، داده و seed/بودجه، معیار پذیرش، آزمون‌ها، شواهد، و **STOP gate** مشخص. ابتدا شواهد موجود را وارسی کن؛ صرف وجود Issue باز مجوز تکرار اجرا نیست.
3. مستندات نظری در `tex/` و `research_journal/`؛ شواهد تجربی خام و کد در `code/experiments/<slug>/`. تغییر علم، عدد، داده یا کد تنها با مأموریت صریح و کنترل مناسب مجاز است. تاریخچه خطاها را از دادهٔ خام حذف یا مخفی نکن.
4. کامیت‌های کوچک و معنایی روی همان شاخه؛ Git SHA و Git blob برای بسته‌های حساس. برای کد/LaTeX از PR واحد به `main` استفاده کن؛ PR را در حالت Draft تا تکمیل گیت نگه دار. **مرج یا حذف شاخه تنها با تأیید مسئول مجاز** و پس از تأیید حفظ تاریخچه و شواهد.
5. پس از مرج، مالک یا مدیر مقایسه ancestry/tree، تبار فایل‌ها، وضعیت PR و وابستگی workflow/branch protection را بررسی کند. تنها سپس شاخه موقت حذف شود. شمار `ahead=0` به‌تنهایی مجوز حذف نیست؛ Issueهای #56/#57 هشدار تاریخی‌اند، نه لیست زنده قابل اجرا. **شاخه قبلی `editorial/ch3-language-reference-audit-01` پس از PR #76 ادغام شده ولی تا تأیید مالک حفظ می‌شود.**

- هر یافته: **ادعا/تعریف → فرض‌های دقیق → اثبات یا روش آزمایش → نتیجه → حد اعتبار → رأی علمی/منبع ثابت → محل متن پایان‌نامه**.

- برای دادهٔ آزمایش، `README_FA.md` یا `REPORT_FA.md`، منشأ، commit/manifest، پارامترهای دقیق `K,n,d,β,λ,H`، خانواده سیاست، Train/Validation/Test، ماسک، تعریف معیارها، seed مولد/solver، بودجه/گام، raw `JSON/CSV`، checksum، نسخه موتور، وضعیت آزمون و محدودیت استنتاج الزام است.
- ابعاد مستقل را از زیرمجموعه‌های تو‌در‌تو و checkpointهای یک داده جدا کن. خروجی شکست/توقف، raw و snapshot باید محفوظ بماند. نسخه `legacy,clip` معیار KL را به نسخه exact بدون محاسبه جدید تغییرنام نده.

- برای بازگشایی پژوهش: ابتدا `README_FA.md` → `SCIENTIFIC_DECISIONS_FA.md` → `EXPERIMENTS_FA.md` → `PROVENANCE_FA.md` → raw/Issue مرتبط.

## ۳. ممیزی و کنترل کیفیت
- هر ادعا/اجرای مهم: بازبینی فرض‌ها، حالت‌های مرزی، مثال نقض، بازتولید عددی با کد و داده منجمد، تفکیک رأی مستقل از خودممیزی مدیر. عدم وجود ابزار یا بودجه `NOT_RUN` است.
- کنترل کد: CI/pytest، checksum، وضعیت preflight و تهدید تغییر داده پس از صحت‌سنجی (TOCTOU)، گزارش PASS/FAIL/NOT_RUN دقیق و نسخه قابل تکرار. هر اصلاح عددی نیازمند رگرسیون fixture شکست است.
- کنترل LaTeX: `label/ref/eqref/cite`, محیط‌ها، نمادها، فرمول‌ها، تصویر، XeLaTeX با بسته‌های لازم و بازبینی **PDF واقعی مالک** برای overfull، حروف فارسی، شکل و ارجاعات؛ صرف اسکن ایستا اثبات سلامت PDF نیست.
- تغییر ریاضی اساسی: مثال نقض/برهان مستقل، رأی قابل حسابرسی، مدیر گیت تصمیم. اگر شواهد کافی نیستند، `UNVERIFIED` بماند، نه PASS.
- قبل از PR: diff و نام تمام فایل‌ها، مسیر raw/manifest، اشتراک ادعا و داده، آزمون اجراشده/نشده، مسائل باز و محدودیت‌ها. PR شامل checklist و SHA نهایی باشد. مدیر پس از بررسی تصمیم می‌گیرد؛ پژوهشگر خودسرانه merge نکند.
